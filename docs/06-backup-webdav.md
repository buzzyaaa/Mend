# 06 · 备份、恢复与 WebDAV 预留

## 1. 数据落盘位置

- 数据库单文件存于应用数据目录（Tauri 平台约定路径；便携版可为程序目录下 `data/`）。设置弹窗"备份与恢复"区块展示实际数据目录（后端同时返回库文件路径，当前界面只展示目录）。
- 目录内只放：SQLite 库文件、必要的非敏感配置；日志不含敏感数据。

## 2. 手动拷贝备份 / 迁移（R11，MVP 必做）

适用场景：把库文件拷到 U 盘 / 移动硬盘自行保存，或迁移到另一台电脑。

### 2.1 拷贝前要求

- **先锁定或退出程序**，避免拷贝到正在写入的不一致文件；SQLite 事务虽降低损坏概率，但热拷贝仍有风险。
- 备份文件与主密码配套：换机器后用同一主密码解锁；主密码丢失，拷贝出的文件也无法解密。

### 2.2 恢复步骤（文档化，界面提供入口）

1. 退出目标机器上的 Mend。
2. 将备份的库文件放回应用数据目录（覆盖前先保留现有文件）。
3. 启动 Mend，输入原主密码解锁。
4. 校验：条目数量、分类与备份前一致。

### 2.3 文件完整性

- 库文件头部/meta 中保存 schema 版本与校验信息；恢复时做完整性检查（能打开、meta 可读、DEK 可解包）。
- 恢复失败不覆盖现有库：先导入临时位置校验通过，再替换。

## 3. 应用内加密导出 / 导入（R11，MVP 必做）

| 能力 | 说明 |
| --- | --- |
| 导出备份 | 通过系统文件对话框选择保存位置，导出独立加密备份文件（如 `mend-backup-YYYYMMDD.mendbak`）；内容为密文，受主密码保护；文件名不含敏感信息 |
| 导入恢复 | 通过系统文件对话框选择备份文件，校验格式与完整性、输入主密码；提示将覆盖的库会留底后确认；**默认覆盖恢复**，冲突规则记录到本地 `local/DEVLOG.md` |
| 与手动拷贝关系 | 手动拷贝库文件是兜底手段；应用内导出是带校验的推荐方式 |

> 备份文件格式在阶段 5 定义：版本号 + 加密库快照 + 认证标签；确保未来版本能识别旧备份。

### 3.1 已实现的 `.mendbak` 格式

文件为二进制容器，头部非敏感，正文为整库密文：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 8 | 魔数 `MENDBK01`（末两位为版本，目前 `01`） |
| 8 | 16 | salt（与建库时一致，用于派生密钥） |
| 24 | 4 | Argon2id `memory_kib`（u32 LE） |
| 28 | 4 | `iterations`（u32 LE） |
| 32 | 4 | `parallelism`（u32 LE） |
| 36 | 24 | XChaCha20-Poly1305 nonce |
| 60 | 余下 | 整库快照密文（AAD = `mend:backup:v1`） |

- 备份密钥 = 主密码 + 头部 salt/KDF 派生的 KEK（与解锁用的是同一把），因此**换机器后输入同一主密码即可恢复**；主密码丢失备份不可解。
- 导入策略：**默认覆盖恢复**。流程为"解密 → 写临时文件 → 校验（能打开、meta 可读、主密码能解包 DEK）→ 现有库改名 `mend.db.bak-<毫秒时间戳>` 留底 → 临时文件替换 → 锁定会话"；任何一步失败都不动现有库。
- 恢复后必须用该备份的主密码重新解锁（会话内的旧 DEK 已随库替换失效）。

## 4. WebDAV 接入预留（R10，MVP 只做接口与结构预留）

目标：后续可把**加密后的库快照**推送到 WebDAV（坚果云/Nextcloud/ownCloud/标准 WebDAV），远端只存密文。MVP 不实现真实联网同步，但代码结构与配置要留好扩展点。

### 4.1 预留设计

- Rust `sync/` 模块定义 trait：

  ```rust
  trait VaultSync {
      async fn test_connection(&self, config: &WebdavConfig) -> Result<()>;
      async fn upload(&self, config: &WebdavConfig, snapshot: &[u8]) -> Result<()>;
      async fn download(&self, config: &WebdavConfig) -> Result<Vec<u8>>;
  }
  ```

- `WebdavConfig` 结构：`base_url`、`username`、`app_password`（加密存本地配置）、`remote_path`、`enabled`；阶段 5 已落地 `mend-core/src/sync.rs`（trait `VaultSync` + `DisabledSync` 占位实现），全程不发请求。配置与 trait 已在后端落地，但**设置弹窗暂未提供 WebDAV 入口**（原"未启用"占位已移除）；待真实同步启用时再补设置项。
- 同步对象：整库加密快照（密文），与本地库文件结构一致；远端不存明文、不存主密码。
- 配置项存 `meta` 表（密码字段加密）。

### 4.2 后续实现时再定的事项（不在 MVP 承诺）

- 手动同步 / 定时同步 / 变更触发同步。
- 多设备冲突合并（基线快照 + 双侧副本保留，冲突项不静默覆盖）。
- 并发更新重试、同步历史记录。
- 仅上传密文；WebDAV 密码只用于访问远端，与主密码用途分离。

### 4.3 安全约束（后续实现必须遵守）

- 远端文件始终是密文；任何日志不记录 WebDAV 密码与库内容。
- 网络请求仅在用户主动配置并触发同步时发生；默认离线零请求。
- 下载恢复前先在临时位置校验认证标签与完整性，通过后再替换本地库。

## 5. 备份策略建议（写进用户文档）

- 至少一份离线备份（U 盘/移动硬盘）+ 可选一份 WebDAV 密文备份。
- 修改主密码后重新导出备份（旧备份用旧主密码解密）。
- 备份文件视同敏感材料，妥善保管物理介质。
